# UI audit, 8 November 2026

A page-by-page list of visual bugs, broken controls, layout problems and places where the UI disagrees with the docs. Everything here was seen in the running app unless it is marked **(code)**, which means it was found by reading the source and confirmed where possible.

## Status

Most items were fixed in PRs #51, #52, #54, #55, #57, #58, #60 and #63, and the docs were brought in line with the app afterwards. The findings below are kept as they were found. These were skipped or only partly done:

- **P0-4 and PT-13:** adapted. #45 removed the urgent card on purpose, so urgent reports now open the sent screen. That screen scrolls to the top and shows a bold status with an icon. The "Close" button was not renamed, because that would bring back the instruction #45 removed.
- **PT-14:** partly done. There is no endpoint that checks a token without signing in, so the role picker still comes before the expired-code screen. The expired screen's wording was fixed.
- **PT-20:** partly done. The page has no QR scanner, so "Scan again" is an instruction on the signed-out screen, not a button.
- **D-4:** partly done. A row click now opens the visit, but the visit is a page with tabs, not a sheet. The docs now say so.
- **P0-9:** the charge nurse can't use Flag higher, because the API allows only the triage nurse to flag.
- **VA-6:** after an assessment, the outcome is shown only until the page reloads, because the timeline event doesn't carry the disposition.
- **TY-3:** the README now describes the system font stack. Noto Sans Gurmukhi and the Arabic and Urdu fonts are still not self-hosted.

## How this was checked

- **Build:** `origin/main` at `c5dfc1c` (after #44, the Auth0 staff session), run with `vite` and the MSW mocks. Your local `main` checkout is two PRs behind this.
- **Roles:** triage nurse, physician and charge nurse from the demo picker, then patient and companion through the visit QR.
- **Widths:** 1440, 1100, 768, 500, 390, 360 and 320 px. The narrow widths used a same-origin iframe, because Chrome will not shrink the window below 500 px.
- **Extra conditions:** Arabic (right to left), 200% root font size, keyboard focus, and a DOM script that checks page overflow, small targets, heading order, `document.title` and font-size count.
- **Flows walked:** enrolment (errors, CEDIS lock, pager, success); board filters; visit Overview, Assessment, Timeline and Visit management; vitals errors and save; acknowledge; record assessment; show QR; physician search and filters; patient sign-in, takeover, every check-in question, the circle check, the four dock buttons, a new symptom report, leaving, sign-out; 404.
- **Checklist:** WCAG 2.2 AA, NHS and GOV.UK design systems, Apple HIG, Material 3, NN/g, Baymard, Carbon tables, and alarm-fatigue guidance ([checklist and sources](#appendix-the-checklist-used)).

**Severity**

- **P0:** broken, hides information, or unsafe for a patient. Fix before the demo.
- **P1:** clearly wrong, confusing, or fails WCAG AA.
- **P2:** polish and consistency.

Each item has an ID so it can become an issue or a checklist line.

## Appendix: the checklist used

The rules the findings were measured against, condensed:

- **WCAG 2.2 AA:**
  - text contrast at least 4.5:1, and borders and icons at least 3:1 (1.4.3, 1.4.11)
  - targets at least 24 px (2.5.8), and 44 px on patient screens (2.5.5)
  - focus not hidden under sticky bars (2.4.11)
  - no 2-D scroll at 320 px (1.4.10)
  - 200% text with no loss (1.4.4)
  - a unique title on every page (2.4.2)
  - errors that name the field and the fix (3.3.1, 3.3.3)
  - help in the same place on every page (3.2.6)
- **Forms (GOV.UK, Baymard):**
  - error summary on submit, with focus moved to it and "Error: " in the title
  - inline errors that clear once fixed
  - submit buttons not disabled
  - radios for 2–7 options
  - no `<datalist>` for critical input
- **Typography (GOV.UK v6, NHS):**
  - patient body text 19 px; staff body text at least 14 px
  - about 6–7 sizes in the scale
  - one `<h1>` per page and no skipped levels
  - short uppercase eyebrows only
- **Colour (NHS, GOV.UK, Carbon):**
  - each status colour has one meaning
  - red for danger and errors only; blue for interaction only
  - status shown by colour plus text plus icon
- **Tables (NN/g, Carbon):**
  - numbers right-aligned
  - sticky header in its own scroll container
  - a whole-row click target that also has a real link
  - fixed column widths
  - distinct empty and filtered states
- **Clinical dashboards (Joint Commission, AHRQ):** guard against alarm fatigue. Use interruptive styling for actionable items only and keep the overview quiet.
- **Multilingual (W3C, Apple HIG):**
  - `dir` and `lang` on the page and on any foreign-language fragment
  - mirror arrows and progress, but not logos
  - language names written in their own language
- **Motion and layout (web.dev):**
  - CLS of 0.1 or less, with space reserved for errors and banners
  - `prefers-reduced-motion` honoured
- **Print and QR:**
  - a quiet zone of at least 4 modules, at least 2 cm printed
  - instructions in the patient's language
  - `break-inside: avoid`
